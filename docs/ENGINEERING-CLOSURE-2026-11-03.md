## Security and scope limitations — real outstanding engineering

- Public storefront is still a static demonstrator with `catalog/trusted_signers.json` empty, `catalog/release_history.json` empty, `catalog/android_repository.json` repository null, no approved public Windows package map, no approved third-party web origins or commercial publisher backend. We did NOT publish any production APK/EXE, private code, certificate fingerprint or package link.
- ClamAV real signature scan on **debug** APK plus Trivy source scan and archive CRC is not an assurance that a third-party production app is malware-free, privacy-safe or legally cleared. Actual owner-approved real binary dynamic/sandbox screening must be performed separately. The owner CLI fails when actual signer/provenance, approved permission policy, fresh signature DB or bytes mismatch.
- Live HTTPS byte parity checks the **first-party HamApp Pages storefront** at run time, not unrelated third-party web app provenance, immutable release commits, or future availability. Product web-release trust roots still require independently reviewed immutable HTTPS origin.
- Need an independently approved real app/developer signer/certificate and owner publication permission. Stable encrypted owner-controlled offline F-Droid signer and independently tested recovery, signed public HTTPS F-Droid v2 index, official F-Droid client real subscription and two authentic signed-version installs/update/recovery are not delivered.
- Production Windows Authenticode/official WinGet mapping and interactive installer/update/rollback on owner's device have not been accepted. WinGet registry readback, hosted unsigned preview and debug tests are narrower.
- Multi-publisher authenticated private submission, moderation, roles, licensing and payment implementation remains product-scope engineering (not completed); do not turn public Pages into a paid/private file-upload portal without a concrete approved architecture.
- Critical GitHub admin gate [Issue #31](https://github.com/rezamahrm100-ops/hamapp-store/issues/31): enforce main required PR/reviews/checks; GitHub connector lacks administration write permissions. CODEOWNERS alone does not enforce controls.
