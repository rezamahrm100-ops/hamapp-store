# بستهٔ عملیاتی خصوصی هَماپ — اجرای محلی

## ابزار بازبینی ناشر — در همان بسته، اختیاری

از PR #99، اجرای `HamApp-Service-Setup.cmd` هر دو تصویر Docker را از
**همان نسخهٔ سورس** می‌سازد؛ اما **فقط سرویس TLS قرنطینه**
(`publisher-intake`) را اجرا می‌کند. تصویر `owner-review`
حاوی ابزارهای متن‌باز F-Droid، ابزار امضای اندروید، GitHub CLI و ClamAV
است و تنها با انتخاب صریح مالک و آماده‌بودن پوشهٔ خصوصی قابل اجراست.
این تصویر در حالت عادی هیچ درگاهی باز نمی‌کند و به‌صورت خودکار
هیچ فایل ناشری را تأیید، امضا یا منتشر نمی‌کند.

نحوهٔ معرفی کلیدها و پوشهٔ خصوصی، شروط صحت پایگاه ضدبدافزار و
اجرای کامل بررسی در
`docs/OWNER-REVIEW-DOCKER-TOOLCHAIN-2026-11-08.md` و
`docs/OWNER-PRIVATE-REVIEW-INTEGRATION-2026-11-08.md` توضیح داده
شده‌اند. نتیجهٔ CI جایگزین کلید و هویت تولیدیِ واقعی نیست.


این بسته، سرویس TLS دریافت برنامه‌های ناشران را **با استفاده از همان بک‌اند
موجود** اجرا می‌کند؛ بک‌اند تازهٔ موازی نمی‌سازد. نسخهٔ آزمایشی با Docker
Desktop روی ویندوز و یک فایل `HamApp-Service-Setup.cmd` قابل راه‌اندازی است.

نصب‌کننده و سرور پیش از نصب کاربر **ساخته و آمادهٔ پیکربندی** هستند؛ سرویس
پیش از اجرا روی رایانهٔ مالک، آنلاین تلقی نمی‌شود.

## راه‌اندازی بدون کدنویسی

در ویندوز ۱۱ با Docker Desktop و Python 3.12:
`deployment/HamApp-Service-Setup.cmd` را اجرا کنید؛ شناسهٔ ناشر را بنویسید.
برای استفادهٔ محلی، گواهی اختیاری است؛ در صورت عدم ارائه، یک گواهی
**صرفاً محلی و آزمایشی** برای `localhost` تولید می‌شود. هیچ کلید
امضای اندروید یا ویندوز ساخته نمی‌شود.

اسکریپت دقیقاً یک پروژهٔ Docker به نام `hamapp-private` و یک volume
اختصاصی ایجاد می‌کند، توکن ناشر را در اولین اجرا می‌سازد، آن را در DPAPI
کاربر جاری ویندوز ذخیره می‌کند، گواهی عمومی سرور را در `LOCALAPPDATA`
قرار می‌دهد و اتصال TLS را آزمون می‌کند. آدرس پیش‌فرض تنها
`https://localhost:8766` است. هیچ `docker prune`، تغییر فایروال، راه‌اندازی
سرویس دیگری یا نصب اپ‌های کاربر انجام نمی‌دهد.

`HamApp-Service-Status.cmd`: مشاهدهٔ وضعیت؛
`HamApp-Service-Tokens.cmd`: افزودن/چرخش/ابطال توکن‌های ناشران؛
`HamApp-Service-Stop.cmd`: توقف فقط همین سرویس بدون حذف داده.

## حد مرزهای عملیاتی

این سرویس عمداً فقط توکن و فایل را پذیرش/قرنطینه می‌کند. **ورود به صف
بررسی به معنی تأیید هویت واقعی، انتشار عمومی، امضای نرم‌افزار، پرداخت
یا ثبت رسمی توسعه‌دهنده نیست.** کلیدهای امضای انتشار باید در محیط امن
مالک نگهداری شوند. برای سرویس عمومی باید گواهی قابل‌اعتماد دامنه،
DNS، پراکسی امن و تأیید مالک فراهم شود؛ گواهی آزمایشی `localhost`
برای اینترنت عمومی معتبر نیست.

منبع Android F-Droid مستقل از سرویس ناشر است؛ WinGet رسمی Windows
نیز از قبل در رابط هَماپ فعال است. سرویس شخصی منتشرکنندهٔ بستهٔ
جدید نیست مگر فرآیند تأیید و امضا تکمیل شود.
